# 자동 정리 추천 고도화

사용자가 2026-09-13에 승인한 범위: 불확실한 이유별 확인, 비슷한 파일의 묶음 지정, 명시적으로 저장한 답변을 다음 추천에 재사용한다.

## 동작

- 기존 파일 조사, 프로젝트 이름·별칭·본문 단서, 종류별 기본 추천 위에 사용자 규칙을 적용한다. 외부 AI나 네트워크 호출을 추가하지 않는다.
- 일반 위치 지정은 해당 파일의 검토 선택으로만 남는다. `포함한 파일로 규칙 만들기`에서 적용 범위와 일치 파일을 확인하고 저장해야 재사용 규칙이 생긴다.
- 규칙은 원본의 **직속 부모 폴더 + 파일명 접두어 + 동일 확장자**로 한정한다. 하위 폴더나 다른 위치로 확장하지 않는다. 빈 확장자는 확장자가 없는 파일에만 일치한다.
- 접두어는 Unicode 정규화와 대소문자 무시를 사용한다. 미리보기와 실제 추천은 동일한 매칭 함수를 사용한다.
- 서로 다른 규칙 목적지가 겹치거나, 문서의 프로젝트 단서와 규칙이 충돌하거나, 저장 당시 프로젝트 위치·폴더가 사라지면 확인 대기로 남긴다. 새로운 목적지로 조용히 대체하지 않는다.
- 규칙 추천은 매번 다시 계산한다. 규칙을 끄거나 삭제하면 현재 미확정 추천에도 반영한다. 사용자가 직접 지정한 선택은 원본 버전이 같은 동안 유지한다.
- 같은 원본 위치·확장자·프로젝트 후보·현재 목적지·확인 이유의 파일을 함께 검토할 수 있다. 파일명 접두어는 묶음 확인의 단서일 뿐 프로젝트 소속 근거로 사용하지 않는다. 그룹 배정은 해당 그룹의 포함한 파일에만 적용하고 보류한 파일은 원래 위치와 대기 목록에 남긴다.
- 규칙 파일은 별도 `ReviewRules.json`에 최대 200개 저장한다. 이전 프로젝트·대기 목록 형식은 유지한다. 읽기 실패나 외부 변경이 있으면 기존 규칙 파일을 덮어쓰지 않는다.
- 규칙은 이동안을 추천한다. 기존 이동안 확인·실행·원본 변경 검사·덮어쓰기 방지·프로젝트 보호·기록·Undo를 그대로 통과해야 실제 파일이 이동한다.

## 화면 기준

기존 `DESIGN.md`의 마지막 지시와 현재 프로젝트 검토 화면을 직접 구현 기준으로 고정한다. 정사각 타일과 벤토 배치, 파란색·흰색·검정·중성 회색, Theme 글꼴과 검정 PillStyle을 유지한다. 기존 목록 안에 접을 수 있는 묶음 확인·규칙 목록을 추가하고, 규칙 저장 화면에서 원본·확장자·목적지·실제 일치 파일을 표시한다. Refero의 craft-details에서 입력 라벨, 키보드 접근, 상태 표시를 적용한다. 검토하는 파일 목록은 재배열하지 않는다.
