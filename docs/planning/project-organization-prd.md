# TILES — 프로젝트와 템플릿으로 정리하기

2026-09-11 개정. 새 구현 범위와 수용 기준은 이 문서를 따른다. Hazel 조사와 이전 단일 파일 PRD는 `hazel-analysis-and-tiles-prd.md`에 보존한다. 구현·검증 결과는 별도로 기록한다.

## 목표와 디자인 계약

바탕화면에 쌓인 파일을 사용자가 선택한 프로젝트와 템플릿에 맞춰 정리한다. 사용자는 조건식을 작성하지 않는다. 파일의 종류·내용에서 얻은 근거와 사용자가 선택한 보관 방식을 연결하며, 알 수 없는 항목은 확인할 수 있게 남긴다.

- 기존 6×4 벤토 그리드, 워드마크, 퍼즐 이동 원리, 폰트와 흰색·검정·중성 회색·파란색 역할을 유지한다.
- 상단 Dock의 위치·크기·폴더 카드·등장 모션을 유지한다. 드래그 중 후보와 hit target을 고정한다.
- 입력을 받은 뒤 검토 패널을 펼친다. 파일을 잡고 있는 동안 OCR·권한 대화상자·프로젝트 설정을 실행하지 않는다.
- 버튼과 결과 미리보기가 기본이다. 짧은 대화는 폴더 트리 편집을 위한 보조 입력이며 지원하지 않는 요청을 이해한 척하지 않는다.

## 두 가지 입력, 같은 검토

1. 직접 정리: Finder 파일 1~500개를 상단 `정리 추천`에 놓거나 앱의 파일 선택/드롭을 사용한다.
2. 감시 정리: 바탕화면 등 감시 폴더와 대기 시간을 사용자가 선택한다. 기본은 끔이며 선택 범위 바로 아래의 일반 파일만 확인한다.
3. 두 입력 모두 같은 프로젝트 정보, 내용 분석, 파일별 목적지 미리보기, 실행·기록·Undo를 사용한다.

## 상단 Dock 상태와 행동

| 상태/입력 | 행동 |
|---|---|
| 평상시 | 숨기고 일반 포인터 입력을 통과시킨다. |
| 파일 드래그 진입 | 파일 개수, `정리 추천`, 최대 두 개의 기존 목적지와 `바로 이동` 표시. |
| 추천 타깃에 드롭 | 드래그 종료 후 검토 패널을 연다. 파일은 원래 위치에 남으며 정리 위치가 아직 없어도 입력을 받는다. |
| 기존 폴더에 드롭 | 선택한 목적지로 묶음을 검사 후 이동한다. 충돌이나 변경 시 덮어쓰지 않는다. |
| 드롭 전 취소 | 이동 없이 닫는다. 네이티브 드래그 한 번당 실행은 최대 한 번이다. |
| 드롭 후 검토 | 패널은 자동으로 닫히지 않는다. 닫거나 보류하면 파일을 이동하지 않는다. |
| 실행 완료 | 실제 성공/부분 완료/실패를 구별하고 폴더 열기와 되돌리기를 제공한다. |

## 프로젝트와 폴더 트리

- 필요한 정보: 프로젝트, 정리할 기준 폴더, 템플릿. 이미 아는 값은 다시 묻지 않는다.
- 기존 프로젝트/폴더를 재사용하고 새 프로젝트 이름과 구조를 생성 전에 수정할 수 있다.
- 템플릿: 간단한 프로젝트, 종류별, 작업 단계별, 업무 문서별, 수정 월별.
- 필요한 가지부터 만든다. 월별은 파일 수정 월을 사용한다고 표시하며 12개 빈 월 폴더를 미리 만들지 않는다.
- 기본 구조 예: `참고자료 / 작업파일 / 결과물`. 파일 형식만으로 결과물·초안·승인 상태를 판단하지 않는다.
- 추가/삭제/이름 변경 및 `결과물을 웹용과 인쇄용으로 나눠줘` 같은 지원하는 요청으로 트리 초안을 편집한다. 적용 전 디스크는 변경하지 않는다.
- 트리만 만들기와 파일을 함께 정리하기를 실행 버튼에서 구별한다. 기존 폴더를 덮어쓰거나 내용이 있는 폴더를 삭제하지 않는다.

## 추천과 확인

1. 파일명·형식·날짜를 먼저 확인한다.
2. 내용 확인을 켠 경우 지원 텍스트/PDF의 본문과 이미지·스캔 PDF의 제한된 OCR을 사용한다. 외부 서버 전송은 없다.
3. 실제 이름·본문에서 찾은 프로젝트명/별칭을 근거로 표시한다. 짧은 토큰의 우연한 부분 일치를 소속으로 확정하지 않는다.
4. 여러 후보는 사용자가 선택한다. 함께 끌어왔다는 이유로 모두 한 프로젝트에 귀속시키지 않는다.
5. 프로젝트와 세부 역할을 별도로 선택한다. 선택한 행들에 한 번에 적용할 수 있으며 그 선택을 전역 규칙으로 자동 확대하지 않는다.
6. 읽기 실패, 미지원, 내용 확인 꺼짐, 글자 없음, 소속 불명확을 구별한다. 임의 신뢰도 숫자는 표시하지 않는다.
7. 실행 직전 선택 파일·원래 위치·최종 목적지·만들 폴더를 확인한다. 보류/제외 항목은 이동하지 않는다.

## 감시

- 위치와 대기 시간을 저장한다. 감시는 앱 실행 중 동작하며 로그인 실행을 대신 설정하지 않는다.
- 마지막 수정 후 대기 시간이 지나고 상태가 안정된 항목을 확인 대기에 넣는다. 미완료 다운로드, 숨김/폴더/패키지/별칭/심볼릭 링크/클라우드 미다운로드 항목은 실행 대상으로 삼지 않는다.
- 동일 파일 버전은 반복 제안하지 않는다. 변경된 파일은 다시 대기하며 재시작 후에도 큐를 복원한다.
- 이 버전은 확인 후 이동한다. 새 대기 항목은 묶어서 알리고 알림/대기 목록에서 공통 검토 패널을 연다.
- 감시 끄기와 제안 보류를 제공한다. 드롭 파일의 부모 추론을 상시 감시 동의로 재사용하지 않는다.

## 실행과 복구

- 기존 안전 검사, 같은 로컬 볼륨, 원본 보호, 참조 확인, 스냅샷/identity 확인, 무덮어쓰기 이동, 저널, Undo를 재사용한다.
- 계획 중 파일이나 폴더를 만들지 않는다. 기존 부모와 새로 만들 부모의 상태를 실행 전에 다시 확인한다.
- 여러 파일/하위 목적지는 한 실행 기록으로 묶으며 일부 실패를 전체 완료로 표시하지 않는다.
- 폴더만 만든 실행도 기록한다. Undo는 앱이 만든 동일한 폴더가 비었을 때만 제거하고 사용자 내용은 보존한다.
- 기존 설정·기록 호환성을 유지한다. 프로젝트/검토/감시 상태는 버전이 있는 별도 파일에 저장하며 읽기 오류 시 덮어쓰지 않는다.

## 수용 기준

- 첫 사용: 다중 드롭 → 프로젝트/기준 위치/템플릿 → 트리 수정 → 미리보기 → 실행 → Undo.
- 기존 프로젝트: 구조 재사용, 일괄 프로젝트/세부 폴더 지정, 일부 보류.
- 이름이 불명확한 PDF와 스캔 이미지의 실제 인식 근거, 미지원/빈 텍스트의 확인 필요 상태.
- 혼합 프로젝트, 동명 파일, 변경된 원본/부모 identity, 보호 파일, 취소·부분 완료.
- 폴더만 생성 후 Undo, 재시작 후 기록/설정/대기 복원.
- 실제 Finder 다중 드래그로 추천/바로 이동 확인, 일반 포인터·기존 배치·모션 회귀 확인.
- 생성한 임시 파일만으로 내용/identity 보존·복구를 검증한다. 개인 바탕화면은 설정 없이 감시하거나 정리하지 않는다.

## 구현 순서

1. PRD와 현재 디자인을 기준으로 범위를 고정한다.
2. 프로젝트/템플릿/내용 분석과 안전한 배치 계획을 구현한다.
3. 설정·트리·추천 검토 화면과 상단 입력을 연결한다.
4. 감시 대기 큐와 공통 검토 진입을 연결한다.
5. 자동 검사, 임시 파일 통합 검사, 실제 UI 확인 후 앱을 빌드하고 GitHub에 소스와 문서를 올린다.
