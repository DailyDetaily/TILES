# TILES

여러 파일을 프로젝트와 폴더 템플릿에 맞춰 정리하는 macOS 네이티브 앱입니다. 파일명·지원 문서·이미지 OCR에서 확인한 근거를 보여주고, 사용자가 이동안을 확인한 뒤 실행합니다. 분석과 기록은 이 기기 안에서 처리합니다.

## 사용하기

1. Finder 파일 **1~500개**를 앱에 놓거나 `⌘O`로 선택합니다. 화면 상단의 **정리 추천**에 놓아도 같은 검토 패널이 열립니다.
2. 기존 프로젝트를 선택하거나 **프로젝트 만들기**에서 이름, 보관 위치, 템플릿을 고릅니다.
3. **간단하게 · 파일 종류별 · 작업 단계별 · 문서 용도별 · 월별** 중에서 정리 방식을 선택합니다. 폴더를 추가·제외·이름 변경하거나 지원하는 짧은 요청으로 트리를 편집할 수 있습니다.
4. 프로젝트와 하위 폴더를 파일별 또는 선택 파일 전체에 지정합니다. 소속이 불명확하거나 용도를 고르지 않은 파일은 확인 필요로 남습니다.
5. **이동안 확인**에서 원본, 목적지, 만들 폴더를 확인한 후 실행합니다. 완료 화면이나 **기록**에서 한 작업을 되돌릴 수 있습니다.

프로젝트 구조만 만들 수도 있습니다. 트리 편집은 미리보기이며 실행 버튼을 누르기 전에는 디스크의 폴더를 생성·삭제하지 않습니다. 기존 프로젝트에서 트리 항목을 제외해도 디스크에 있는 해당 폴더는 삭제하지 않습니다. 월별 템플릿은 실제 파일 수정 월을 사용합니다. 파일 형식만으로 초안·결과물·승인 상태를 판단하지 않습니다.

상단 Dock의 **바로 이동** 폴더에 놓으면 그 폴더로 묶음을 검사 후 이동합니다. **정리 추천**에 놓으면 파일을 원래 위치에 두고 검토를 시작합니다. 드래그 중에는 내용 분석이나 프로젝트 설정 대화상자를 열지 않습니다. Dock의 위치·크기는 설정에서 편집할 수 있습니다.

## 감시 폴더

**설정 → 감시 폴더**에서 바탕화면 등 한 폴더와 대기 시간을 선택하고 감시를 켭니다. 기본은 꺼짐입니다. 앱이 실행 중일 때 선택 폴더 바로 안의 파일을 확인하며, 마지막 수정 후 대기 시간과 안정 확인을 통과한 파일을 **확인 대기**에 넣습니다. 자동 이동은 하지 않습니다.

기본 대기는 10분, 확인 간격은 45초입니다. 동일 파일 버전의 반복 제안을 막으며 대기 목록은 재시작 후 복원됩니다. 시스템 알림은 별도 허용 버튼을 누른 뒤 사용할 수 있습니다. 로그인 시 실행을 설정하지 않습니다.

## 내용 분석과 보호 범위

- 파일명, 확장자, 수정일을 확인합니다. 내용 확인을 켜면 지원 텍스트, PDF 본문, 이미지와 스캔 PDF의 OCR을 제한된 범위에서 읽습니다. 외부 AI나 서버로 전송하지 않습니다.
- 읽기 실패, 미지원, 글자 없음, 내용 확인 꺼짐, 여러 프로젝트 후보를 구별합니다. 이름·본문에서 실제로 찾은 프로젝트명과 별칭을 추천 근거로 보여줍니다.
- 한 묶음 최대 500개를 확인합니다. 내용 추출은 최대 100개, 파일당 16 MiB, 텍스트 2 MiB, PDF 처음 5페이지와 전체 약 120초의 처리 예산을 사용합니다. 개별 시스템 PDF/OCR 호출은 도중에 즉시 끊기지 않을 수 있습니다.
- 코드 프로젝트, 앱·편집 프로젝트 묶음, 보호한 원본·인증 자료, 숨김 파일, 링크·별칭, 지정 보호 경로는 기존 안전 정책으로 보호합니다. 분석된 파일도 실행 검사에서 제외되거나 중단될 수 있습니다.
- 참조 조사는 선택 파일의 부모 등 제한된 로컬 범위의 지원 텍스트를 대상으로 합니다. 다른 앱의 데이터베이스와 임의 외부 폴더의 연결까지 확인하지 않습니다.
- 같은 로컬 디스크 안에서 덮어쓰기 없이 이동합니다. 다른 디스크로의 복사·이동은 지원하지 않습니다.

기존 **폴더 전체 정리**는 첫 화면 또는 `⇧⌘O`에서 사용합니다. 원본 폴더와 도착 폴더를 고르고 분석 후 항목을 선택합니다. 해당 화면의 `⌘R`은 다시 분석이며 이름 분류·보호 경로는 설정의 고급 규칙에서 편집합니다.

## 기록과 되돌리기

실행 전에 원본 내용·식별자·부모와 목적지 상태를 다시 검사합니다. 변경되거나 이름이 겹치면 덮어쓰지 않습니다. 각 이동과 폴더 생성을 저널에 기록하며, 중단·부분 완료는 전체 완료와 구별합니다.

Undo는 실제 이동한 파일만 되돌리고, 이 작업에서 만든 동일한 빈 폴더만 제거합니다. 이후 편집된 파일이나 원래 위치의 충돌이 사전 검사에서 확인되면 작업 전체의 되돌리기를 시작하지 않습니다. 내용이 추가된 폴더는 남겨 둡니다. 폴더만 생성한 작업도 기록하고 되돌릴 수 있습니다. 재시작 후 기록의 **상태 확인**으로 디스크와 대조할 수 있습니다.

설정·실행 기록·확인 대기 목록은 `~/Library/Application Support/MaterialOrganizer`에 저장합니다. 읽을 수 없는 상태 파일은 덮어쓰지 않습니다. 분석한 본문 전체를 대기 상태에 저장하지 않습니다.

## 디자인

기존 6×4 벤토 그리드, 정사각형 조각 워드마크와 불규칙 슬라이딩 퍼즐 모션을 유지합니다. 흰색·검정·중성 회색에 `#4c92e9`를 사용합니다. 시스템의 동작 줄이기 설정을 따릅니다. 모션 규칙은 [MOTION.md](MOTION.md)에 있습니다.

Pretendard, Manrope, Archivo Black과 해당 라이선스를 앱 리소스에 포함합니다. 제공되지 않은 유료 글꼴을 사용했다고 주장하지 않습니다.

## 빌드와 검증

macOS 14 이상과 Swift 6 도구체인이 필요합니다. 현재 실제 검증 환경은 Intel Mac의 macOS 26입니다.

```sh
swift test -j 4
swift run OrganizerSmoke
scripts/build-app.sh
open dist/TILES.app
```

독립 빌드 경로가 필요하면 `TILES_BUILD_PATH=/tmp/tiles-release scripts/build-app.sh`를 사용합니다. 빌드 스크립트는 현재 Mac 아키텍처의 앱을 만들고 ad hoc 서명(`codesign --sign -`)과 서명 검증을 수행합니다. 공증된 배포본은 아닙니다.

`swift run OrganizerSmoke --fixture`는 UI 검증용 임시 자료를 만듭니다. 출력 경로로 `dist/TILES.app/Contents/MacOS/MaterialOrganizer --demo-root <경로>`를 실행하면 별도 데모 설정과 기록을 사용합니다. 생성한 임시 자료만으로 이동·복구·내용·inode를 검증합니다.

[구현 PRD](docs/planning/project-organization-prd.md)와 [검증 기록](VERIFICATION.md)에 범위와 검증 결과를 구분해 기록합니다. 빌드 산출물, 로컬 검증 캡처와 사용자 설정은 Git에 포함하지 않습니다.
